I would prevent double conversion by using a MongoDB transaction for each conversion. First, I would conditionally deduct points from `point_balances` only if the user has sufficient balance. Then, I would deduct points from the corresponding `point_lots` using conditional updates to ensure the same points cannot be consumed twice. The conversion record, ledger entries, and wallet credit would all be processed within the same transaction, so either everything succeeds or everything rolls back. If two requests happen simultaneously, MongoDB may trigger a write conflict, causing the transaction to retry and check the updated balance before proceeding. I would also use a unique index on `{ userId, idempotencyKey }` in the `conversions` collection to prevent duplicate conversions when a client retries the same request. This ensures that points cannot be converted twice and that the balance, lots, ledger, and wallet remain consistent.
